# Startup assessment formats: evidence and preparation

## What the evidence can support

[OFFICIAL] The [catalog](Startup_Interview_Research_Catalog.md) contains named first-party process examples and employers where only context was readable. It is a small purposive sample, not a market survey. No universal startup round count, DSA difficulty distribution or founder-interview rule is established.

The list below is an [INFERRED] practice classification. Verify which format applies before making it the center of preparation.

| Possible format | What a practice attempt should demonstrate | Clarify before assessment |
|---|---|---|
| Algorithm/live coding | Contract, invariant, complexity and tests | Language, execution and resource rules |
| Debugging/code review | Reproduction, causal hypothesis, focused fix and regression check | Repository/setup and tool permissions |
| Feature implementation | Usable scope, validation, boundaries and checks | Time budget, deliverable and evaluation criteria |
| Architecture discussion | Requirements, ownership, one failure/recovery path and tradeoff | Expected level and domain |
| Project discussion | Personal contribution, alternatives and evidence limits | Depth, presentation format and confidentiality |
| Work trial | Prioritization, collaboration and defensible implementation | Payment, scope, schedule, data/tools and submission handling |
| Customer exercise | Discovery, constraints, acceptance and communication | Hypothetical versus real customer/data exposure |

## Use AI policy as a separate field

[OFFICIAL] PostHog's engineering page distinguishes AI permission for its SuperDay project from a restriction during its debugging session. This is a stage-specific employer policy, not permission for other employers or every PostHog interaction. [Engineering hiring](https://posthog.com/handbook/people/hiring-process/engineering-hiring), undated, accessed 2026-11-02.

Ask for the current instructions for the exact assessment. “AI allowed” does not remove responsibility for understanding the result. “Reference lookup allowed” is a different permission from generated solution assistance.

## Read process variation carefully

Different public pages can use different labels or timings. Preserve their scope and ask which one governs the requisition. A candidate describing one paid trial does not prove all startups use trials; a role with no reported DSA does not establish a company-wide ban on algorithm questions.

## Practice — STAGE-P4-06

**Intermediate; all target engineering roles; company-neutral preparation planning.** You have a practical feature assessment but no tool-policy instructions. How do you prepare and what must be clarified?

<details><summary>Expected reasoning, followup and common mistake</summary>

Practice an independently explainable small feature, tests and a failure path. Ask for permitted resources/AI use, environment, time budget, deliverable and review criteria. Followup: how do you discuss incomplete work honestly? State the implemented path, checks, known defects and next step. Common mistake: assuming production coding habits are automatically authorized in an interview.

</details>
