**ID:** IN4-ZOHO. **Category:** company-neutral engineering preparation. **Difficulty:** Intermediate, with optional advanced followups. **Target:** early-career SDE/backend, AI/full-stack or the selected role; suggested technical/project/design practice. This exercise is **[INFERRED]**, not attributed as an employer question.

**Prompt:** Implement a small contact-management component with validation, duplicate handling, search and a clear storage/API boundary. Explain one rejected design.

<details><summary>Expected reasoning, followups and evaluation</summary>

Agree on identity and duplicate semantics, handle empty/malformed input, define pagination/order and test update/delete conflicts. For a shared service, authorize each object. If AI deduplication is proposed, compare it with a deterministic baseline and define false-merge costs before adding it.

**Followups:** How do you prevent false merges of two legitimate contacts? Which version or conditional-update rule handles conflicting edits?

**Strong indicators:** a precise contract, a concrete correctness/authority mechanism, meaningful edge cases and a supported explanation. **Common mistakes:** naming tools without a flow, inventing throughput/quality evidence, or conflating a local test with production behavior.
