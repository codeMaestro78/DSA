**[INFERRED]** For service-software backend/full-stack work, practice tenant isolation, workflow state and API correctness. ## Original preparation exercise — attempt first

**ID:** IN4-FRESHWORKS. **Category:** company-neutral engineering preparation. **Difficulty:** Intermediate, with optional advanced followups. **Target:** early-career SDE/backend, AI/full-stack or the selected role; suggested technical/project/design practice. This exercise is **[INFERRED]**, not attributed as an employer question.

**Prompt:** Add a support-ticket summarizer to a multi-tenant service. A retrieved note belongs to another tenant and a generated answer contains a plausible unsupported claim.

<details><summary>Expected reasoning, followups and evaluation</summary>

Prevent unauthorized evidence from entering retrieval/reranking/context; then evaluate claim support and citation alignment separately. Define failure/abstention and human review. Distinguish an operationally successful model request from a useful correct support outcome.

**Followups:** Can an accurate summary still be unauthorized? How would you distinguish a wrong citation from missing retrieval evidence?

**Strong indicators:** a precise contract, a concrete correctness/authority mechanism, meaningful edge cases and a supported explanation. **Common mistakes:** naming tools without a flow, inventing throughput/quality evidence, or conflating a local test with production behavior.
